# Architecture

How the pieces fit, file by file. Numbers and examples come from real races; they're the evidence for the thresholds in the code.

## Telemetry in

The game sends UDP packets at 20 Hz. They're decoded into dicts in one shape whatever the year, and `RaceState` keeps the latest of each plus the history the rest needs.

- `engineer/spec.py` — every 2026 packet layout as declarative structs. Field names = spec minus `m_` (except `m_2026Regulations` → `is2026Regulations`). `SPEC_SIZES` is the "Size:" line from the spec; tests assert they match.
- `engineer/codec.py` — Struct/F/Str mini-DSL; one `struct.unpack_from` per packet, rebuilt into dicts. Also `pack`/`blank` for tests and synthetic data.
- `engineer/formats.py` — UDP formats 2025 (F1 25) and 2024 (F1 24) as edits to the 2026 layouts (22 cars, uint8 ids, float g-forces, F1 24's 48-char names, fields dropped), applied by field name. Every packet size matches that year's spec and the field order matches EA's C structs. Same header since F1 23, so `packetFormat` picks the layout.
- `engineer/decode.py` — bytes → (packet_id, dict) **always in the 2026 shape**: older formats are widened (`codec.widen`): 24 car slots (padding = blank, inactive cars), fields that format doesn't send are `None` (`[]` for arrays of structs), so the UI shows "–" rather than a made-up 0. It rejects formats other than 2024–2026, unknown ids and wrong sizes. The event union is decoded by code. Checked by re-encoding the Austria race as 2025 and 2024: the brief at L22 and every call came out identical, except that F1 24 sends no retirement reason.
- `engineer/lookups.py` — ID → name tables. TEAMS/DRIVERS/TRACKS/NATIONALITIES are generated from the spec appendix text; the rest hand-copied from spec comments.
- `engineer/state.py` — `RaceState`: latest packet per id, per-car session history + tyre sets, lap positions, events ring, packet stats. Resets on sessionUID change. Thread-safe via `state.lock`.
- `engineer/laps.py` — per-car record at each lap line (crossing time back-dated by `currentLapTimeInMS`, position, tyre, age, wear, fuel, stops, pit flag; player's peak surface temps for the lap). Owned by `RaceState` (reset per session). Flashbacks: FLBK drops crossings after the rewind time, and a lap number going backwards prunes too.

## Server and dashboard

One process: a UDP thread, an HTTP server for the dashboard and its API, and server-sent events for anything that can't wait for a poll.

- `engineer/server.py` — UDP thread + `ThreadingHTTPServer`. API: `/api/state`, `/api/race` (Race tab), `/api/car?idx=`, `/api/raw?id=`, `/api/logs?since=`.
- `engineer/hub.py` — pub/sub behind the `/api/stream` SSE: `buttons`, `radio` (status), `level` (mic rms, 15 Hz while open), `message`, `reply` (engineer), `quick`. `hello` on connect carries a `build` id; pages reload when it changes (stale JS after a restart cost us once).
- `engineer/view.py` — state → JSON for the dashboard (timing tower rows, car detail, session, raw). `clean()` strips NaN/inf and stringifies ints > 2^53.
- `engineer/glance.py` — `/api/race`: the Race tab's numbers built on `Race` (gaps + trends in words + flag projection for the cars either side, wear per corner + %/lap, fuel delta, ERS, limits x/3, penalties, damage, race log with pit waves collapsed, biggest zone lost/gained), so screen and engineer agree. ~1 ms.
- `web/` — vanilla JS dashboard, no build. `app.js` polls `/api/state` at 4 Hz and owns tabs (`#race` default, `#timing` etc. in URL); `race.js` is the Race tab, glanceable mid-race: position/lap/last/best, ahead/behind cards, tyres, car, where the time goes, race log, and the radio feed (latest answer large; the floating radio card hides on this tab). `panels.js` is pure render functions → HTML strings; `radio.js` renders the server's radio state from SSE — header badge, the broadcast-style TEAM RADIO card (fixed, every tab), and the Radio tab (mounted once, updated in place).
- `engineer/log.py` — `[LEVEL] [module] msg {json}` logger + ring buffer for the dev log viewer. Console and ring follow `RE_LOG_LEVEL` / `RE_ENV`; the server also calls `to_file`, which writes INFO+ to `captures/logs/<start>.log` for that run whatever the console shows, and logs anything that would otherwise only reach stderr: an uncaught exception or a thread dying (`[crash]`, with the traceback). The first line is the options the server started with. A 25-lap replay logs 19 INFO lines (~2.4 kB); live adds the radio and model lines.
- `engineer/driver.py` + `web/driver.js` — **who's driving**: name + pronouns (he/him, she/her, they/them) in `captures/driver.json` (River, he/him). First load of the dashboard with no name opens a "Who's driving?" dialog prefilled with the game's player name (`from_game`: "River JAMES" → "River James"); the header button changes it later. `GET/POST /api/driver`. The prompts and the team's fact lines are still written about River, he/him; `driver.words()` rewrites our own text at send time (name, his/him/he's, verb agreement for they: "he asks" → "they ask"), never what the driver said. Used on every system prompt (engineer, lead, review, prep), the prep facts, trigger reasons and the team's radio history.

## Recording and the archive

Every session is recorded raw, so old races can be re-read whenever the decoder or the analysis changes. The archive catalogues them and keeps what the strategy side learns across sessions.

- `engineer/capture.py` — `.f1cap` format (`F1CAP1\n` + `<dH` time/len + bytes; `.f1cap.xz` read transparently), `Writer`, UDP replay CLI. Raw bytes so old sessions re-parse after decoder changes.
- `engineer/recorder.py` — always-on per-session recording (game quiet for 120 s, e.g. saved and quit or console off → the file is closed and archived; the same uid resuming opens a second part): a new sessionUID opens `captures/sessions/<date>_<time>.f1cap`, renamed `…_Austria_P3.f1cap` on the first session packet; menu packets (uid 0) dropped. Each new file writes a `recording` row to the radio log (uid, `started` as the archive has it, `wall0` = the wall-clock time of the capture's t=0), so anything stamped with the wall clock (clips, calls, the engineer's voice) can be placed on the packet timeline and in the game footage. On session change it's archived in the background; on server stop, synchronously, and nothing that arrives after that is recorded (the UDP thread used to die writing to the closed file); raw files left by a crash are finished at the next start.
- `engineer/archive.py` — long-term store. Captures stay the source of truth; `captures/archive.db` (SQLite) catalogues `sessions` (track, type, player, position, best), `files` (parts: a server restart mid-session gives two files, one uid), `results` (packet 8, else last lap data; stints), `laps` (every car, sectors, valid), `events` (all but BUTN/SPTP; raw, not flashback-pruned), `imports`. Finishing = index → compress with xz (preset 1: 9× smaller, ~65 MB/hr). `RE_DATA_DIR` moves it all. `reindex` rebuilds the tables from the files.
- `engineer/profile.py` — River's numbers across sessions: `Tracker` follows the player through a capture as the archive catalogues it (lap data read every 0.5 s; a flashback back over a lap line keeps that line's row, which before overwrote it with mid-lap fuel and wear and skewed burn and tyre life; at each lap line fuel kg + delta, compound, age, wear, the set's life estimate, SC, pit) → `player_laps`; the AI's wear over set age on his compound, median per wheel → `field_wear`; the forecast, his sets and the weekend structure at the end → `session_data`. Reads: `fuel()`, `tyre_life()`, `distance()`, `latest_here()`. A session's parts each add their laps (Spa race 2 is five files). Backfilled by `archive reindex` (~25 s for everything).
- `engineer/pitstops.py` — **what a stop costs per track**, measured from every car's stops in every archived race with the same `calc.stop_loss` rule as live (`dev pits`: Austria 19.5 s over 20 stops, 17.4–21.9; Montreal 18.5 over 1; Silverstone 21.7 over 1). The game's rejoin estimate was wrong both ways (Silverstone ≈11 s, Austria ≈23). Stints' `endLap` is one before the in-lap (Austria: endLap 12, in-lap 13, out-lap 14). Stops under SC/VSC (from SCAR events, rewound ones dropped on FLBK; lap times summed from lights out at session time 0) and slicks↔wets stops are kept apart; a resumed save repeats earlier laps, so stops are de-duplicated by driver + lap times; only races that started before this one count (so evals never see the future). The brief's PIT line uses this race's stops once there are two, else earlier races here (`here()`, cached per session), else this race's one, else the game's estimate.
- `engineer/usage.py` — every model call (recorded inside `llm.stream`: `role` engineer/dev/eval/judge, `at` = `usage.where(state)` → session uid, type, track) and timings (`metric`: stt_ms, release_ms, tts_ms, call_delay_s, call_expired, call_stale, cut_off, radio_heard/empty) go to `usage` / `metrics` tables in archive.db through one writer thread (callers often hold the state lock). `session_cost(uid)` is kept in memory for the header and the coming pit-wall budget. Costs start 2026-10-14 14:26: the radio log never stored cost, so nothing earlier to backfill.
- `engineer/diagnostics.py` + `web/diagnostics.js` — `/api/diagnostics` and the Diagnostics tab: cost this session / today / all time by role, by session type (per session), recent sessions, evals and dev spend for the week, latency p50/p90 per step (session vs week), counts (cut-offs, dropped calls, empty presses, model errors), feed health. Header shows `$` for the session (`/api/state` meta.sessionCost).

## Reading the race

The models are never asked to do arithmetic. Everything they read is worked out here first and written as words where signs get misread.

- `engineer/race.py` — `Race(state)`: one snapshot under `state.lock` that the brief, strategy, calls and Race tab all read (me, my lap data, `car()`/`status()`/`damage()`/`telemetry()`, `pos`, `name`, `neighbour(step)`, `loss()` = green-flag pit loss and its source, `at_flag(gap)`, `battery()`). Public API: nothing outside reaches into `Brief`.
- `engineer/calc.py` — the arithmetic: gap now from the game's live time to the leader (the last line both crossed when either car is in the pit lane or untimed; game-quirks.md has why and the measurements), trend at the line (windows skip any lap touched by a stop: `_settled`), wear %/lap over the stint, deg slope, sector deltas, fuel laps to go, rain lap from forecast minutes, pit loss from stops seen (`stop_loss`: the slowest two laps in a row around the stop = in- + out-lap, wherever the box sits, against the two laps either side of them, or the three before until those are run; the old set's pace alone hid ~3 s at Silverstone where the inters were dying), before any: read off the game's rejoin estimate against the sorted gaps behind, free-stop lap vs the car behind, `slicks_vs_wets` (latest clean lap ≥ 2 cars ran on slicks and ≥ 1 on inters: median of each), rejoin position, fresh-tyre gain the cars that stopped really got (`fresh_gains`: 3 laps before the in-lap vs the first 3 after the out-lap, per old→new compound; Austria L20: Hard→Medium 1.73 s/lap ×11, Medium→Hard 0.84 ×7), else the game's `lapDeltaTime`, sector gaps to another car (avg of last 3 representative laps; best laps in quali).
- `engineer/fmt.py` — text formatting shared by the brief sections (lap times, wheels, gaps, trends in words).
- `engineer/trace.py` — per-distance trace of every car's last 4 laps (lap distance → lap time, speed, brake) + best clean lap. Zones run from one of River's brake onsets to the next; `compare` gives time lost/gained per zone, apex (min) and top speed deltas, braking-point difference. Laps with pit/SC/invalid flags are kept but not "clean"; sparse laps (< 10 Hz, AI driven off-screen) dropped.
- `engineer/wear.py` — **where on the lap the tyres wear**, every car. Packet 10 sends each car's wear as a float at 10 Hz, so every increment goes into a 25 m bin of that lap (flashbacks cut the lap from the rewind point, tyre changes ignored, pit/SC laps left out). The AI all wear within a few % of each other (Silverstone L3: RL 1.75–1.98 %/lap), so the field's median is the yardstick. **By sector** (River's call: corners take too much of his attention until he knows tracks by turn number; sector boundaries come from the session packet's `sector2/3LapDistanceStart`). Brief section WHERE THE TYRES GO: your %/lap per wheel vs the field, then for your fastest-wearing tyre each sector's rate vs the field's with the sector time gained/lost to the car ahead, and which sector the extra concentrates in — named only if ≥ 1.15× the whole lap's ratio, else "spread evenly round the lap" (Silverstone L11: 1.9–2.0× in all three; Spa FP1: S3 2.9× vs 0.9–1.3×). Like with like: his laps on the set he's on now, against cars on the same compound (each lap is tagged with stops + compound; Spa race 2 said "3.2× the field" for fresh mediums against his own inters laps and everyone's hards). Nobody else on his compound → no comparison. Proactive call (triggers `_overwear`): "Rear-left's wearing 1.9 times the field's rate. About 77% by the flag. It's all round the lap." / "Mostly in sector 3.", said again at 1.4/1.8/2.2× and as the flag projection passes 60/75 %. Silverstone replay: L3, L9, L11.
- `engineer/grip.py` — **rear grip by sector**, his laps only: rear slip angle at speed, wheelspin (share of full-throttle time with a rear slip ratio > 0.10) and rear surface temps, in 25 m bins per lap (packets 6 + 13; flashbacks cut like wear). The AI's tyre temps aren't simulated (fixed per compound and track: Austria medium 85 °C, hard 90; Spa hard 105), so the yardstick is the first 3 clean laps on this set against the last 2 (plus sectors already done this lap). Flags: sliding ≥ 1.4×, wheelspin ≥ 2× and +7 points, a rear ≥ 12 °C hotter. In WHERE THE TYRES GO ("rears" lines) and a call once per set and sector ("Rears are sliding more in sector 1 than at the start of the set. Look after them through there."). Austria #8: S1 sliding from L22 (River: "the back is slipping out"), gone by L25 ("rear feels good again"); also L11 (worn mediums) and L18 (after his TC change). Montreal: nothing. Silverstone/Spa inters: temps +22–30 °C as the track dried. Eval aut-l22-slip 3/3.
- `engineer/incidents.py` — the race log: River's track-limits warnings with lap + distance (from lap-data counters, which revert on flashback like the game does), penalties, other cars' stops (position in → out), retirements, contacts and passes involving River, and passes between the cars within 3 places of him ("between the cars around you: ALONSO passed NORRIS L4 (after 3 changes of place, L2–4)", a fight collapsed to who came out ahead; Spa sprint: "Alonso just saved me" meant Alonso got between him and Norris and the brief didn't say so). Pruned on FLBK.
- `engineer/strategy.py` — **stop plans in code** for the brief and the calls (all take a `Race`): `rain()` (forecast → lap), `fresh_gain()` (measured from ≥ 2 same-kind stops this race, else the sets' estimate), `worn_in()` (laps until the fastest-wearing tyre reaches `WORN` = 70 %, a guess until River's pace vs wear sets it; replaces the game's `lifeSpan` in the brief, Race tab and the low-life call: it said "~17 laps left" at Silverstone L11 with the RL done in 7), `rain_plan()` (stay out and stop once for inters vs stop now and again: extra stop − new-tyre gain × laps to the rain), `sc_stop()` (SC 50 % / VSC 65 % of the green-flag loss: a rule of thumb, labelled as one, until a race has cars that stayed out; Montreal can't say, every car stopped on L10–11), `sc_wait()` (each lap waiting for an SC costs the fresh gain; pays only if one comes within saved ÷ gain laps), `easing()` (raining now: when the forecast drops below 50% and whether rain returns), `slicks()` / `slick_call()` (on inters: each slick's gain from the sets' `lapDeltaTime` and its `lifeSpan`; pick the quickest that lasts the laps left × `LIFE_MARGIN` 1.15, call at ≥ `SLICK_CALL` 1.0 s/lap), `dry_stop()` (on slicks with a stop still to make, either a second compound owed or the fitted set heading past `WORN` by the flag: the best set of each compound he can fit this lap (not one he's run while the rule is owed; a stint on inters or wets counts, a sprint owes nothing, `Race.sprint()` = the first race of a weekend with more than one), its `lapDeltaTime` against the fitted set and the wear it reaches by the flag; pick the quickest under `WORN`. The wear is his fastest-wearing tyre's rate this stint × the fitted compound's `usableLife` ÷ that set's, not the set's `lifeSpan`: at Brazil L13 his 11-lap Medium had `lifeSpan` 8 with the RR at 50% and 4.4%/lap, 4 laps from `WORN`. The scaling matched the field there (AI Softs wore the RR 1.27× their Mediums; 21/17 = 1.24), and his one lap on the 5% Soft wore its RR ~6.7%, above the 5.4 the scaling gave. So at L13 the 5% Soft, 0.95 s/lap quicker than the new Hard, reaches ≈71% at the flag and the line picks the Hard; with no wear rate yet it falls back on `lifeSpan` ≥ laps left × `LIFE_MARGIN`). The sets' slick estimate was right at Spa race 2 (crossed over mid-L5, the field boxed at the end of it) but undersold mediums over hards (0.9 s/lap vs ~2 measured). No SC odds: the game doesn't send any.
- **Tyre target** (`strategy.target`/`target_text`): his fastest-wearing tyre at the end of the planned stop lap (or the flag once he's stopped) at this stint's rate; past 70% → the %/lap saved by matching the field's wear in the sector(s) the extra comes from (or all round the lap) and how many laps of that get there, else the lap the stop has to come by. In the PIT WALL section (planned stop) and the brief's YOU lines ("to the flag", after a stop); `triggers._target` calls the team once per stint and target lap, fallback call "Rear-left won't make lap 19 at this rate. Save it in sector 3 for about 4 laps." The team weighs managing against bringing the stop forward (`pitwall.md`). Silverstone L11 for a L19 stop: RL 77%, matching the field all round saves 2.5%/lap, about 4 laps.
- `engineer/brief.py` — `build(state)` → the text brief the models read (text only; numbers come from `Race`, `calc`, `strategy`) (race: session, SITUATION (SC phase and restart, or a red flag: suspended, free tyre change, standing restart, until the restart's lights go out), forecast + rain lap (raining now: "easing: below 50% from +5m ≈ lap 7; no more rain forecast: the track is drying", not "rain likely from +0m", which Kimi read as "raining and getting wetter"), SLICKS on inters (each slick's gain and life, "→ box this lap for Medium", cars already on slicks, measured slick vs inter laps), YOU, PIT, STOP when a stop is still to make (each set he could fit this lap with its pace and wear at the flag, the pick and why not the quicker one, what the cars that stopped took and what the cars within 3 places are on), RACE LOG, WHERE THE TIME GOES, FIELD with spelled-out trends; practice/quali: WHERE THE TIME GOES + best-lap table). WHERE THE TIME GOES = sectors and corner zones vs the cars either side (race) or the fastest (quali), plus your last lap vs your best. Trends and sector deltas are words ("closing on you 0.20/lap", "S3 you're 0.071 quicker") because models flip bare signs (Kimi read S3 −0.071 as "a tenth down"). `tests/test_brief.py` runs a synthetic 4-car race through the real decoder.

## The engineer

One fast model answers the driver; templated calls go out unprompted at sensible moments.

- `engineer/llm.py` — streaming chat client (stdlib): OpenRouter by default, any OpenAI-compatible endpoint with `RE_LLM_URL` + `RE_LLM_KEY` (OpenRouter-only fields dropped, `stream_options.include_usage` instead, no key needed for a local server). Key from env or `.env`, never logged. `provider.sort = latency`: default routing sent Kimi to a 4–6 s provider; sorted it's ~1–2 s (GLM ~0.5 s). Error bodies are reduced to the message (they carry the account's user id). With `llm.TRACE` set (the server, and `dev prep --run` whose plan the race uses; not the other dev tools or evals), every call is appended to `captures/llm/<YYYYMMDD>.jsonl`: start time, role, why, session uid, model, the full messages, the reply as streamed, and stats or the error (a call that fails halfway keeps what came). 3–5k prompt tokens a call (usage table, 2026-10), so ~15 kB a row.
- `engineer/prompts/` — `engineer.md` (system prompt; the live brief is appended), `pitwall.md` / `pitwall-review.md` / `pitwall-prep.md` (the team) and `judge.md` (evals). `engineer.prompt(brief, question, history)` builds the messages for live, `dev ask` and evals alike.
- `engineer/engineer.py` — answers every finished radio message (spoken or typed) on one worker thread: fresh `brief.build()` + last 4 exchanges from the past 90 s only (reset per session; older ones got repeated as current facts: Austria L22 "the set's fresh, zero percent wear" on a 10-lap-old hard, "Piastri 1.3 back" from an answer 15 min earlier) → stream → `reply` hub events (thinking → streaming → done/error, with model, first-word ms, cost). Acknowledgements ("copy", "mm-hmm") get no reply, and nor does a bare "yeah"/"no"/filler (`ANSWERS`) unless our last word in the past 30 s ended in "?" — a human engineer lets a stray word go. Prompt rules that mattered on real data: use the brief's computed lines, never estimate a number the data doesn't give, make the call instead of offering a menu. When River is telling, not asking ("Alonso just saved me", "I was pushing hard to hold off Norris"), take it as true, acknowledge in a few words with at most one fitting fact, no warnings or gap trends (unprompted calls cover threats), never correct him or say how hard to push; annoyed → "Copy." (Spa sprint live answers warned "he's closing 0.62, keep it tidy" / "don't lift" while he was deliberately lifting and coasting and saving battery to defend). Manage/push advice by part of the lap comes only from WHERE THE TYRES GO (River asked for it 2026-10-14): manage through the sector it's concentrated in (lift and coast a little more into its corners), or the whole lap if it's spread, keep pushing if the tyres will make it; no other driving tips.
- `engineer/numbers.py` — **every figure in an answer checked against the brief before it's said.** The engineer hands the voice one sentence at a time as it streams; a sentence with a figure the brief and the question don't back isn't said (logged as WARN, kept on the reply row as `held` and shown under the reply on the Radio tab), and if nothing of an answer is left it says "Can't give you a solid number on that one." Its history keeps what was actually said, so a follow-up doesn't build on the held figure. What counts as backed: rounding to as many places as were said, tenths in words, a lap time by its seconds ("a 16.7"), metres to one or two figures or in km, "around/about N" for the nearest 5 or 10 at 10 and up; a figure with a unit (%, °C, P, lap, kg, km/h) only against one with the same unit. Measured on 96 Kimi answers at 8 moments of 5 races (129 sentences): nothing held back. The rehearsal's "43%" (brief: RL 39%, +4.7%/lap) is held. Moving each figure in those answers by 10% or a few units, it catches 88–100% of moved percentages, 96% of figures over 100 and about 45% of other figures under 100 (gaps, counts: a 4k-character brief holds most small numbers somewhere), so it's a backstop for the model doing its own arithmetic, not a proof.
- `engineer/quick.py` — **the quick brief** on the second button (no model): `brief(state)` → a call row (`topic: quick`), said at once through the voice and logged like a call. Race: position, the cars either side (gap, "closing 0.2 a lap" / "you're catching" when last lap moved it by ≥ 0.1, else nothing), the most worn tyre; red flag / SC first when out. Qualifying: position and the gap to P1 (or the margin to P2), from the game's order and each car's best lap, then last lap vs best. Practice: last lap vs best ("your best" when it was) and the most worn tyre.
- `engineer/calls/` — **proactive calls** (races only). `scan.py`: `scan(race, mem)` returns calls worth making, from `events.py` (limits, penalties, contact, passes, stops, SC, rain, damage, flag), `gaps.py` (within a second, closing, last lap), `tyres.py` (worn, uneven, overwear), `plans.py` (slicks, rain plan, fuel); `caller.py`: `Caller` delivers them; `common.py`: priorities, `call()`. What they cover: track-limits warnings (2nd says one more is a penalty), penalties, contact, passes/being passed (low, skipped around own stop), neighbour stops/retirements, safety car deployed (+ "a stop now costs roughly 9 seconds instead of 18" when the set is 5+ laps old and 3+ laps are left; the SC type comes from the SCAR event, which arrives a few seconds before `safetyCarStatus` flips) / in this lap (battery, cold tyres) / green, rain starting, new damage (rebuilt when said, so a second hit right after the first reads the same and is said once: Brazil front wing then rear wing came out as two identical calls 18 s apart; a flashback that undoes it re-arms), last lap, chequered flag (when River's `resultStatus` turns finished: `CHQF` fires as the flag comes out for the leader, 250 m before the line at the Spa sprint), a neighbour within a second (from the game's live `deltaToCarInFront`, which moves every few hundred metres: the line gap made it a lap late at Spa race 2, said after he'd dived Alonso; once per car until 2.5 s apart again; dropped at delivery if they've swapped places), a neighbour closing (needs a 2-lap trend and the weaker of last-lap/trend ≥ 0.25/lap; "within a second in N laps" or "about X at the flag" in the last 8 laps; 3-lap cooldown per car), fastest-wearing tyre ≤ 3 laps from `strategy.WORN` at his rate (not the set's `lifeSpan`), rain plan (staying out to stop once for inters saves ≥ 5 s and the rain is ≤ 10 laps away; again if the forecast moves it 3+ laps), box for slicks (on inters, the quickest slick that lasts is ≥ 1.0 s/lap quicker: urgent, once a stint; Spa race 2 replay says it mid-L5, before the field boxed), uneven corner wear, fuel behind target. Wording is templated from the numbers (no LLM) and each call's `text(race)` is re-run at delivery, so a stale fact becomes None instead of being said. `Caller` (own thread, 5 Hz, session-time based so replays behave like live) holds calls until a straight (throttle ≥ 95 %, no brake, steer < 0.15 for 1 s, not in the pit lane); urgent ones (SC, penalty, rain, flag) go at once; 6 s between calls; expire by ttl; never while River's talking or an answer is in progress; a red flag is called ("Red flag, red flag.") and the SC phase calls the game sends after it are dropped, as is an SC call still waiting (`Race.red_flag()`: an `RDFL` with no `LGOT` after it; docs/game-quirks.md); flashback clears the queue, and a new session drops everything still waiting, the team's calls too (one that arrived after the game went quiet was said in the next race); joining mid-race says nothing about the past. Published as SSE `call` (also in `hello`) → Race tab feed, interleaved with messages; `Engineer.said` adds them to the follow-up history. Calls are not on the floating radio card. **Verbosity by voice:** "less chat" → quiet (urgent only: SC, penalty, rain, slicks, flag), "more info" / "talk to me" → chatty (adds passes, contacts, neighbours' stops, retirements, lap-2 position; contacts were 5 calls in 9 laps at Spa, and he knows when he's hit someone), "normal chat" → default (urgent + normal); handled by `Caller.command` via `Engineer.commands` before the model, answered locally ("Copy, only the important stuff."). Resets to normal on a server restart.
- `engineer/crew.py` — `assemble(hub, state, …)` wires engineer, radio, voice and calls; used by `server.main` and `dev serve` (`live=False`: spend logged as `dev`, no timings, never against the replayed session).

## The pit wall

Stronger models behind the engineer that make the strategy calls. Design notes in [pitwall.md](pitwall.md).

- `engineer/pitwall/` — **the strategy team** (River: the team decides, the engineer relays; it only decides alone when there's no time to ask). `triggers.py`: `scan(race, mem, box)` → reasons, once each: SC/VSC deployed, rain starting, the forecast rain lap moving 3+ laps or going, slicks quicker (`strategy.slick_call`), a car within 3 places stopping, River stopping, his fastest-wearing tyre ≤ 5 laps from `WORN`, new damage, past the planned box lap; slicks and rain carry the code's own call as a fallback. `wall.py`: `PitWall` (own thread, 1 Hz, session time): plans asked for on first seeing a race; non-urgent reasons gathered 10 s and at most one run a lap; urgent ones (SC, rain, slicks, damage, his question) at once; routine check after 5 laps / 8 min; $2 a session budget, past it only urgent + questions. A run = lead (Sonnet 5.5, `prompts/pitwall.md`: CALL / SAY / WHY / BOX, plus A/B/C + ACTIVE when asked) on the engineer's brief + PIT WALL + its own recent notes + the last 5 min of radio + why it's called; then the second opinion (Gemini 3.8 Flash, `pitwall-review.md`: AGREE / DISAGREE) in the background, a disagreement shown in the next run and the engineer's brief. SAY goes out as an engineer call (`Caller.push`, topic `team`, a newer one replaces one still queued; the Caller then skips its own slicks/rain-plan calls) and only for decisions or answers: early prompts gave driving tips and track-limits nags on routine runs. Strategy questions (`STRATEGY` regex) → engineer says "Copy, checking." and the team answers through the calls; under SC/VSC, in the pit lane or past 85% of the lap the engineer answers itself from the PIT WALL section and the team reviews it after. "go plan B" switches plans (`command`). `notes.py`: parsing, the brief's PIT WALL section (plans, planned stop, the call while ≤ 3 laps old, a disagreement), `notes` table in archive.db (reloaded for the same uid after a restart). `/api/pitwall` → Pit wall tab (`web/pitwall.js`: plans + strat chat), `/api/race` `team` → the Race tab's plan card, Diagnostics shows the budget and run latency. Replays (`dev triggers --run`): Montreal 7 runs $0.10 (SC L11 → "box this lap for mediums", then "no more stops"); Austria 9 runs $0.13 (box called L11, River boxed L12; the reviewer caught a misread gap); Spa race 2 box for mediums at L5, same as the code's call.
- **Race prep** (`pitwall/prep.py`, `prompts/pitwall-prep.md`): the game sends nothing for the race until he's past the strategy screen, so after qualifying the Pit wall tab's "Prepare the race" (or `dev prep --run`) builds the plan from the archive: next session from the weekend structure, race laps ≈ his usual share of the F1 distance (305 km, Monaco 260, sprint 100; ~35%), grid from qualifying, the race's forecast samples (the quali session packet carries them), his sets left (after qualifying or a shootout the lives are halved and, for a main race, a new Hard added, as the race will have them: Monza quali said Soft 18 / Medium 25, the race gave Soft 9 / Medium 12 / Hard 17, and the prep's estimate from quali is 9 / 12 / 16; practice lives are already the race's and are left alone; docs/game-quirks.md), fuel burn per km and how his fuel delta moved in each race, his tyre life against the game's estimate (dry 0.93–1.23×, wet 0.50–0.68× after the flashback fix), pit loss. **Fuel is computed** (`profile.fuel`, `prep._suggest`): the fuel delta's change per lap by condition (lap 1, dry green, heaviest dry stint, wet green, SC), never whole races. The game's target matches his dry burn (Montreal +0.00/lap, Austria ±0.02), so the start delta is about what's left at the flag (his leftover fuel); SC laps +0.27; wet burnt *more* than the target (Silverstone −0.10/lap, Spa −0.01). SUGGESTED FUEL = a full dry race with no SC at his heaviest dry stint ends at +0.3 (`FLOOR`), plus a wet case when the forecast has rain (`_wet_laps`) or ≥25%; the model takes it (Zandvoort +1.1, the old prompt wandered +0.4…+1.5). His wear per wheel against the AI on the same compound (`WEAR VS THE AI`, from `field_wear`): dry FL 1.7–2.3×, FR 1.2–2.1×, rears 1.0–1.5×, so the front-left limits a stint, not the rears, so the AI's stop laps aren't his; set life at his rate uses that compound's own ratio once there are 2 stints. The code also lists every legal dry one-stop (two different dry compounds; each stint within that set's life at his rate → the box window); for a sprint, which has no compulsory stop, it lists instead which sets last the distance (`_no_stop`), leaves out the AI's stop laps and has no compound rule to check (the sprint at Brazil was first planned with a stop from pole), notes when his tyre numbers all come from the front while he starts in the pack, and when the AI made its first stop in his dry races (40–52% distance). The team returns FUEL / START / CALL / plans; a CALL that starts and boxes on the same compound (`prep.check`; Sonnet once wrote used Soft → new Soft) gets one retry told why; saved to `captures/pitwall-prep.json` (12 h, same track) and seeded as the race's plans when it loads, the first run checking them against the live race. River's brief ("damage control, few rewinds") from the tab or "tell the team …" on the radio is kept in `captures/pitwall-brief.json` until changed and goes into every team run. Zandvoort 2026-10-14, after the options: Medium start, run past the AI's stops, box L14–17 onto a Soft, fuel +1.2; the reviewer wanted the new Soft rather than the 7% used one.

## Radio and voice

Push-to-talk on a controller button, local speech-to-text, and a local voice back. Apple Silicon only (MLX).

- `engineer/radio.py` — server owns the radio. UDP Action 1 opens/closes (hold default), UDP Action 2 publishes `quick` and starts each `on_quick` on its own thread (crew: the quick brief; presses arrive inside the state's packet handling, under its lock, so running it there deadlocked the UDP thread); either can be any button (`--radio-button`, `radio.button()`: a name from `lookups.BUTTONS` or a UDP action number). Mic runs continuously into a 0.3 s pre-roll; frames kept only while open; 0.25 s post-roll; 30 s auto-close. Every clip saved to `captures/radio/*.wav` (gitignored). No VAD — the button is the segmenter, but a clip whose loudest 100 ms is under `SILENT_RMS` (0.008) never reaches the speech model: parakeet transcribes silence as "Yeah." (accidental presses mid-corner, Spa 2026-10-14; over all 40 clips everything under 0.01 was empty or "Yeah.", the quietest real question 0.0157). Messages carry `clip`, `clipStart` (wall clock of the clip's first sample) + `loud`; `radiolog.py` appends every message and the engineer's reply (or why it stayed silent) to `captures/radio/messages.jsonl` → `dev radio`, plus, live only, every unprompted call as made (`call`, the team's lines included) and every stretch of the engineer's voice as played (`spoken`, below); Radio tab has ▶ clip / save per message (`GET /api/clip?name=`). Tests point radiolog/clips at a temp dir (`tests/__init__.py`). The folder is `archive.DATA / "radio"`, so `RE_DATA_DIR` moves it with the rest. `POST /api/radio {pressed}` is the Space-key fallback; `POST /api/ask {text}` is a typed question (Radio tab → Ask), handled exactly like a spoken one. `radio.listeners` gets every finished message (the engineer subscribes). `POST /api/fixes {heard, meant}` / `POST /api/fixes/forget {heard}` manage taught fixes (Radio tab → Fixes panel; "fix…" on a message prefills it).
- `engineer/stt.py` — parakeet on one dedicated thread (MLX binds its Metal stream to the loading thread — lesson from Sprocket). Feed **float32** arrays straight to `get_logmel` → `generate`; bf16 input breaks the STFT view.
- `engineer/lexicon.py` — corrects transcripts before anything acts on them: spelled acronyms ("D R S"), fixes the driver taught (`fixes.json` in the data folder), then sound-alike matching (metaphone + Jaro-Winkler) against this session's driver names, team/track names and radio jargon. Messages keep `heard` (raw) + `text` (fixed) + `changes` [{heard, meant, how}] so a guess can later be confirmed over the radio. Guards learned the hard way: common English (wordfreq zipf ≥ 3) is never fuzzed ("nurse" ≠ Norris); multi-word matches are names only and must start with the same letter ("a safety car"); jargon must sound exact; possessives stripped. `tests/test_lexicon.py` has an ordinary-speech corpus that must come through untouched — add to it whenever a false positive shows up.
- `engineer/tts.py` + `engineer/spoken.py` — **the engineer's voice**, local on MLX. `Speaker` has two threads (synth owns the model, as stt.py; player writes to `sounddevice` in 50 ms blocks so a stop is instant). Spoken: each finished sentence of a streamed reply (`Engineer.speak`), local replies ("Copy, only the important stuff."), and proactive calls (`Caller` said-callback); the Caller also treats `speaker.busy()` as busy so calls don't pile on. Keying the radio (`radio.on_open`) calls `stop()`: playback cuts and anything asked before that moment is dropped. `spoken.speakable()` rewrites text first ("0.7 a lap" → "seven tenths a lap", "3 s" → "3 seconds", "1:06.986" → "one oh six point nine eight six", "VSC" → "V S C") and applies `engineer/pronounce.json` respellings for names the engine gets wrong (checked through misaki's phonemes, not by ear). Engines: kokoro (bm_george, bm_daniel, am_adam…), soprano, kitten, qwen3 (style prompt, 7× slower). Measured on the M3 Air for a 7 s call: Kokoro ~0.5 s warm (4–11 s for the very first call, paid at startup), Soprano ~0.3–0.55 s, Kitten ~0.7 s, Qwen3 ~3.3 s. `--radio-fx` band-limits to 300–3400 Hz with a little saturation. Live, each played segment is kept as `captures/radio/spoken/*.wav` with a `spoken` row (text, part, clip, `start` wall clock, `played` seconds, `cut` if the driver keyed over it); segments dropped by a cut before they played leave a wav nothing points at. SSE `speech` {state: loading|ready|speaking|error}; `hello.speech`. No UI for it yet.

## Dev tools and evals

Everything here works from the archive, never the live server.

- `engineer/dev.py` — dev/test bench over the archive: loads a session straight into a `RaceState` up to `--lap N [--into S]` (no UDP, never touches the live server; a race to L21 takes ~18 s), then prints the brief, asks the engineer offline, or serves a dashboard + engineer on :8078 (typed questions; `--play X` keeps replaying from there).
- `evals/cases.toml` (gitignored: the cases point at River's recordings) + `engineer/evals.py` — **strategy evals** from River's real races. `ask` cases: rebuild the brief at a moment (session by uid, `at` or `lap`+`into`), ask the engineer model exactly as live, then a judge model (Sonnet 5.5) checks the answer against `must`/`never` using `facts` (what really happened, which the engineer never sees); plus house rules in code (≤ 40 words, never "the game"/"the data"). `calls` cases replay the race through the Caller (`dev.replay_calls`) and expect or forbid a call. Results → `evals/results/evals-*.json`. After WHERE THE TYRES GO (2026-10-14): calls 2/2, Kimi 2/10. **After measured tyre life, wear vs the cars around you, pit loss per track (2026-10-14 afternoon): Kimi 8/16** (×2); sil-l11-tyres 3/3 ("worn out by lap 18, before the flag, spread round the lap so manage everywhere"). **After Spa race 2 fixes (2026-10-14 13:30): calls 3/3, Kimi 6/10 ×1; the three Spa race cases pass 6/6 ×3** ("No, box for Medium: the quickest that lasts to the flag; Hard is 0.3 a lap slower"). sil-l11-box flips between stay out and box (1/3): the RL reaching `WORN` 70 % "at L18, before the flag" on an 18-lap race pushes Kimi to box, though the stop cost 23–25 s; aut-l22-slip 2/3 (like-for-like wear now says 1.3× the cars on hards, and Kimi mentions it). Still failing: sil-l13-fresh-inters (no pit loss: no earlier Silverstone green stop, no stop seen yet, so no rejoin gap; quotes the sets' 0.84 gain), sil-l13-cant-hold (gives no clear plan, and once invented "sector two": the resumed save has no wear by sector). **Baseline 2026-10-14: Kimi 2/5, Sonnet 5.5 1/8 on the four Silverstone strategy cases, both failing the same way** — the brief hands them the game's numbers, which were wrong for River: `lifeSpan` "~17 laps left" (RL actually heading for ~75% at the flag), `lapDeltaTime` fresh inters 0.5–0.84 s/lap (measured 1.8), the rejoin-estimate pit loss "≈11 s" (measured 23–25), and no wear-vs-field line or rejoin gap. A brief problem, not a model problem.
- [radio.md](radio.md) — what a real engineer would say and when, worked out from the Montreal race: talk windows from River's own throttle/brake trace, proactive calls replayed against that race, driver questions → data → gaps, RS-confirm flows, the commit-point rule (never flip a box call in the run to pit entry), debrief mode. **Read before building `engineer.py` or proactive calls.**
- [pitwall.md](pitwall.md) — plan for the team behind the engineer: strat chat feed, pre-race plans A/B/C the engineer and radio can reference, practice data goals, event-triggered model runs with a heartbeat and a per-race budget, and cost/latency tracking with a Diagnostics tab.
